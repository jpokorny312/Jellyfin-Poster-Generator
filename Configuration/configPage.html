Poster Logo Composer

Builds a Primary image per movie/series from a textless TMDb poster with the item's logo composited over a blurred (no color tint) fade at the bottom. Among the available textless posters, the one whose bottom area is calmest (best suited to show the logo clearly) is chosen automatically. The same logo is also saved as the item's Logo image, and the highest resolution, best rated TMDb backdrop is saved as the Backdrop image. Run the "Compose Poster Logos" scheduled task (under Scheduled Tasks > Library) to apply this to your library. Requires the TMDb metadata provider to be enabled.

Off by default: if no logo matches the resolved language, a language-neutral logo, or English, the item is skipped instead of using a logo in an unrelated language (e.g. a Chinese logo turning up in a German library) just because it had the highest resolution among what was left.
Among logo candidates (in the same language tier) at or above this width, the best-rated one is chosen instead of simply the highest resolution one; resolution is only used as the final tiebreaker. If no candidate reaches this width, the requirement is dropped rather than skipping the item.
How many textless posters are downloaded and scored per item to find the one where the logo will be most visible. Higher values give better results but use more bandwidth and time.
Weight given to how calm/uniform a poster's bottom area is.
Weight given to the actual (unaltered — only blur is ever applied) contrast between this specific logo and the poster's bottom area — this is what keeps e.g. a white logo off a poster whose background is already too bright.
Weight given to raw poster resolution, used as a tiebreaker after flatness/contrast.
Weight given to a poster candidate's TMDb community rating. Nudges a near-tie toward the more popular/vetted candidate instead of an obscure, unrated upload that happens to score similarly on flatness/contrast (e.g. because downscaling blurred whatever text it had baked in).
Weight given to a poster candidate's (log-scaled) TMDb vote count. Kept modest by default since most legitimate posters have few or no votes.
If even the best-scoring textless poster candidate's bottom band has a luminance std-dev above this, Primary generation is skipped for that item instead of compositing on top of it — usually a sign TMDb mistagged a poster as textless when it actually has baked-in text/branding (e.g. from a foreign streaming service's own release image). Off (0) by default; try ~95-110 if you hit a case like this.
How much of the poster's bottom region is analyzed when scoring candidates — independent of, and normally taller than, the fade band height below (which only controls what actually gets blurred). Catches baked-in text/branding positioned just above the blurred band, close enough to clash with the composited logo but outside what gets measured or rendered for the fade itself, which would otherwise go undetected.
How much of the poster's bottom region is scanned for an isolated baked-in text/logo spike (thin horizontal strips are compared against each other). Kept taller than the scoring scan height above, since this signal looks for a localized anomaly rather than an average, so a larger scan doesn't dilute it — it can afford to look further up the poster for a title positioned higher than either fixed band would otherwise catch.
How strongly a detected text/logo spike counts against a poster candidate. Kept assertive by default so it reliably overrides an otherwise deceptively "flat" candidate whose baked-in title was simply diluted by surrounding empty space.

Backdrop Selection

Every time the Backdrop image is (re)generated, existing Backdrop images are replaced with up to this many best-scoring TMDb candidates, so the count stays fixed instead of growing with every run.
Backdrop candidates whose pixel count differs by less than this fraction are treated as equal resolution; rating and vote count then decide between them.

Image Quality

Rewrites TMDb image URLs to request the "original" size before downloading. Disable this only if you want to keep whatever (possibly downscaled) size the TMDb provider itself hands back.
